For a web target, or an embedded web view with a debugging port, recording means injecting a picker into the page and capturing several candidate strategies per element. For a native window with no such port, it means Win32 hooks plus a UIAutomation lookup at the click point — and, where UIA sees nothing, cropping an anchor image from a screenshot.

Which of those to build is decided by tools/probe_native.py, which has not been run against the target application yet. Until then, + Record creates a flow from a working template for you to edit here.

Understudy keeps flows and their evidence in a repository by driving the git you already have, so it works the same against GitHub, GitLab, a self-hosted GitLab, or anything else that speaks git — and inherits your credential helper, proxy and SSH setup.

Clone your flow repository and start Understudy with --workspace pointing at it, or run git init here and add a remote.

No tokens saved.

Stored per host in the same owner-only file, and never returned to this page. A token saved for one host is never sent to another — a GitHub token must not reach a self-hosted GitLab. When Understudy uses one it passes it as a header for the length of a single command; it is never written into .git/config or into a remote URL, where it would sit in the checkout for anyone to find.

GitHub: a fine-grained token with Contents: read and write on the flow repository. GitLab: a project or personal access token with the write_repository scope.
